# S0 用户引导协议

本文件定义 S0 阶段对用户的标准引导流程和话术。所有 agent 执行 S0 时必须按本文组织对话，避免不同 agent 各说各话。

## 使用原则

- 先告诉用户当前处在哪一步，再告诉用户需要做什么。
- 每次只给一个主动作，避免同时抛出多条分叉命令。
- 所有状态都以 `inventory.json`、`validate_record.py` 和 `record.md` 为准。
- 图片识别由 `_tools/vision_route.py` 自动路由到 `VISION_MODEL`，不得要求普通用户手动切换 API 模型。
- 需要用户手动操作时，必须说明操作位置、按钮名称和完成后要点哪个检查按钮。
- 缺资料时不要说“无法继续”就结束，要给出最小补齐路径。
- 解析完成后必须告诉用户下一步建议：S1、S2、S3 或 S4。

## S0 标准阶段

| 阶段 | Agent 要说清楚的事 | 用户主动作 |
|---|---|---|
| 0. 确认项目 | 当前项目代号、项目名称、是否已有 `record.md` | 确认项目是否正确 |
| 1. 打开上传 UI | 本地网页地址和用途 | 打开 `http://127.0.0.1:8765` |
| 2. 上传资料 | 区位图是必选，任务书/地形图/照片是推荐或下游需要 | 把文件上传到对应卡片 |
| 3. 运行检查 | Inventory 检查资料，Validate 检查 `record.md` | 点“运行 Inventory”和“校验 Record” |
| 4. 判断 gate | 区位图是否满足 S0 硬门槛 | 缺什么补什么 |
| 5. 执行解析 | Agent 读取允许读取的资料并更新 `record.md` | 等待 agent 完成 |
| 6. 交付结果 | 已确认事实、低置信字段、待问问题、下一步 | 决定先跑哪个后续阶段 |

## 标准开场

当用户问“我要上传资料/做 S0/下一步做什么”时，使用：

```text
现在我们在 S0：项目档案初始化。

S0 的目标不是做完整设计，而是把资料整理成后续能继续分析的项目档案：
1. 确认项目基本信息
2. 检查区位图是否已上传
3. 盘点任务书、地形图、现场照片等资料
4. 图片资料自动走视觉模型路由，不需要你手动切换模型
5. 把可确认的信息写入 record.md
6. 把缺失或不确定的信息整理成待问甲方问题

你现在只需要先完成资料投递，然后点 Inventory 和 Validate。我会根据检查结果继续解析。
```

## 上传 UI 指引

当用户不知道怎么进入上传网页时，使用：

```text
在 PowerShell 里运行：

Set-Location -LiteralPath "E:\Myproject\Architecture-Design"
python _tools\uploader\server.py

然后打开：
http://127.0.0.1:8765

进入后先选择或创建项目，再把文件放到对应卡片：
- 需求类：任务书 PDF、DOCX、TXT
- 区位图：必须上传，缺它不能跑 S0
- 地形图：DWG、红线图、地形 PDF
- 现场照片：踏勘照片
- 参考案例：甲方给的风格参考
- 聊天记录：甲方沟通记录

上传后点“运行 Inventory”，再点“校验 Record”。
```

## 上传后标准检查提示

当用户说“文件已经上传了”时，agent 必须先运行：

```powershell
python _tools/inventory.py {code} --json --write --require-s0-ready
python _tools/validate_record.py {code} --json
```

然后按结果回复。

如果 inventory 中存在 `visual_asset`，agent 必须继续运行：

```powershell
python _tools/vision_route.py {code} --json --write
```

不要要求用户切换 API 模型。

### S0 gate 通过

```text
资料已经进入项目目录，S0 gate 通过：区位图已存在。

下一步我会读取 inventory，按 read_policy 处理资料：
- PDF/DOCX 用专用提取器读取
- JPG/PNG 图片自动路由到视觉模型，不需要你手动切换模型
- DWG 只登记文件事实，留给 S2
- 旧版 .doc 不直接读取，需转换后再解析

现在可以执行 S0 解析，我会更新 record.md 和 parse_log.md。
```

### 缺区位图

```text
现在还不能执行 S0 解析，因为区位图是硬门槛。

请在上传网页里把区位图上传到“区位图”卡片，支持 png、jpg、jpeg、pdf。上传后点“运行 Inventory”。只要这个 gate 通过，我就可以继续解析任务书和其他资料。
```

### 有旧版 `.doc`

```text
我看到有旧版 .doc 文件。按仓库规则，agent 不能直接读取这种二进制正文。

解决办法有两个：
1. 最推荐：把它另存为 PDF 或 DOCX 后上传到“需求类”
2. 也可以补一份 TXT/MD 版任务书

上传后我会重新跑 Inventory，并用新文件更新 S0。
```

### PDF 已上传

```text
PDF 已经上传并被识别为任务书资料。

下一步是重新执行 S0：我会用 PDF 提取任务书正文，更新项目名称、甲方、建设地点、提交时间、功能节点、风格关键词、待问问题和下游解锁状态。
```

### JPG/PNG 区位图已上传

```text
区位图已经上传，S0 gate 通过。

图片识别会由系统自动处理：我会运行 Vision Route，把 JPG/PNG 交给配置好的视觉模型。系统支持多种视觉模型（OpenAI、Anthropic、Google），会自动选择可用的模型。

如果当前环境还没有配置视觉模型，我也会继续推进 S0，并把地址、坐标、红线范围等不确定项写入待确认问题。

你不需要手动切换 API 模型。
```

### 视觉模型未配置

```text
区位图已上传，但当前环境没有配置视觉模型。

我不会要求你手动切换模型；S0 会自动降级处理：
- 记录区位图已经存在
- 不编造图中信息
- 把地址、坐标、红线范围等内容列为待确认问题

后续只要管理员配置视觉模型（支持 OpenAI、Anthropic、Google），同一张图可以重新跑视觉解析。
```

## S0 完成后的标准交付

S0 写入并校验通过后，使用：

```text
S0 已完成，record.md 校验通过。

本次已确认：
- 项目名称：{project.name}
- 甲方：{project.client}
- 项目类型：{project.type}
- 阶段：{project.stage}
- 已读取资料：{files_count} 个

当前仍需确认：
- {pending_questions_summary}

下一步建议：
1. S4：先整理甲方问题清单，适合马上沟通补资料
2. S1：做区位和场地分析，适合开始汇报前期资料
3. S2：解析 DWG/红线，适合确认用地面积和边界
4. S3：拆解功能和面积需求，适合开始方案规模判断
```

如果只有一个最优下一步，agent 应明确推荐一个：

```text
我建议下一步先做 S4，因为当前还有影响后续设计判断的待确认问题。S4 会把这些问题整理成可以直接发给甲方的话术。
```

## 禁止话术

- 不要只说“上传资料后运行 S0”，必须说清楚上传位置和检查按钮。
- 不要说“随便上传几个文件”，必须明确区位图是硬门槛。
- 不要把 `.doc` 说成已经可解析，必须提醒转换。
- 不要在 S0 完成后直接跳到汇报大纲，除非 S1/S3 已有有效正文。
- 不要让用户猜下一步，必须给出推荐路径和原因。
