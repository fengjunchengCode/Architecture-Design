## 2. 推荐统一设计

不要为每张图纸各写一套绘图逻辑。正确做法是：一套共享图元系统，加每张图纸自己的工具配置。

### 2.1 共享图元：路径 path

路径同时覆盖闭合多边形和开放线段。开放线段不应被限制为两个端点；两点线段只是最简单的开放 path，交通、消防、海绵等图纸必须能表达 N 点路径。

建议字段：

- `geometry.kind`: `path`
- `geometry.closed`: `true` 或 `false`
- `geometry.segments`: 由 `line` 或 `quadratic` 段组成的数组
- `geometry.coords`: 给旧逻辑或预览使用的采样坐标

行为定义：

- `closed=true` 表示多边形。
- `closed=false` 表示开放线段、折线、箭头线，可包含 2 个或更多点。
- 每一段都可以是直线或二次贝塞尔曲线。
- 当前功能分区里的“线段中心点拉弧线”能力，应该迁移成 path 的通用能力，闭合多边形和开放线段都能使用。
- UI 可以保留“点击两个端点快速生成线段”的低摩擦入口，但底层数据和交互必须允许继续添加点，形成多段开放路径。

为什么必须这么做：

- 用户明确要求线段也支持多边形线段的中心点弧线功能。
- 当前 schema 强制 `segments` 闭合，无法表达开放线段，这是后续所有线性图纸的共同阻塞点。
- Mac Claude 审阅指出 P54/P55/P58 的交通、消防、海绵流线都不是单一两点线段，而是多段路径；因此最终计划必须直接按开放 path 实施。

### 2.1.1 旧语义 JSON 向后兼容硬要求

这是最高风险项，必须写进最终 `/goal` 计划和测试。

现有功能分区工作台已经被用户认可，仓库里可能已经存在旧格式的 `functional_zoning.json`。泛化 path 时不得把旧草图读坏。

兼容规则：

- 旧 `geometry.kind="polygon"` 读入时必须迁移为 `geometry.kind="path"` 且 `geometry.closed=true`。
- 旧 `geometry.kind="polyline"` 或 `geometry.kind="arrow"` 读入时必须迁移为 `geometry.kind="path"` 且 `geometry.closed=false`。
- 旧功能分区多边形里的 `geometry.segments` 必须原样保留；其中的 `line` / `quadratic` 段、控制点和闭合关系不得丢失。
- 旧 `geometry.coords` 仍作为采样坐标保留；如果有 `segments`，保存新格式时可以由 `segments` 重新采样生成 `coords`，但不得在加载时破坏原始弧线。
- 旧 `style_hints.fill_enabled=true` 迁移为 `fill_mode=translucent`。
- 旧 `style_hints.fill_enabled=false` 迁移为 `fill_mode=none`。
- 旧 `main_entrance` 等早期交通标记如已存在，应通过 alias/migration 读入为新的统一 `entrance_marker`，避免旧草图直接失效。

验收要求：

- 必须用现有 BQ-PARK 功能分区语义 JSON 或等价 fixture 做回归测试。
- 测试要证明旧 `polygon + segments` 弧线对象加载、保存、再加载后仍是闭合 path，弧线控制点不丢失。
- 测试要证明没有 `segments` 的旧 polygon 也能正常读入和保存。

### 2.2 共享图元：多边形样式

适用于 `closed=true` 的 path。

需要控件：

- 填充模式：无填充、半透明填充、实心填充、斜线填充。
- 填充颜色。
- 半透明填充的不透明度。
- 斜线填充角度。
- 斜线填充间距。
- 斜线颜色或默认跟随填充颜色。
- 边框样式：无边框、实线、虚线、双实线。
- 边框颜色。
- 边框粗细。
- 是否进入图例。
- 图例名称。

兼容现状：

- 当前功能分区的 `fill_enabled=true` 可迁移为 `fill_mode=translucent`。
- 当前功能分区的 `fill_enabled=false` 可迁移为 `fill_mode=none`。

### 2.3 共享图元：线段样式

适用于 `closed=false` 的 path。

需要控件：

- 线条颜色。
- 线宽，使用数值输入或滑块，不能只有固定三档。
- 线型：实线、虚线。
- 每段支持弧线控制点。
- 起点箭头：开/关。
- 终点箭头：开/关。
- 箭头大小。
- 是否进入图例。
- 图例名称。

### 2.4 共享图元：圆形标记

用于：

- 景观节点。
- 垃圾收集点。
- 无障碍设施点。

几何字段：

- 圆心坐标。
- 半径。

需要控件：

- 拖拽调整大小，并始终保持正圆。
- 填充模式：无填充、半透明填充、实心填充。
- 填充颜色。
- 填充不透明度。
- 边框样式：无边框、实线、虚线、双实线。
- 边框颜色。
- 边框粗细。
- 双实线间距。
- 是否进入图例。
- 图例名称。

交互行为：

- 用户点击画布创建圆形节点。
- 用户点击已生成节点可以选中并修改。
- 如果已有选中节点，再创建下一个同类节点时，新节点复制选中节点样式。
- 如果没有选中节点，则复制该对象类型的上一次使用样式。

### 2.5 共享图元：三角形标记

用于：

- 交通出入口。
- 竖向标高点。

几何字段：

- 中心点坐标。
- 尺寸。
- 旋转角度。

需要控件：

- 填充模式：无填充、半透明填充、实心填充。
- 填充颜色。
- 填充不透明度。
- 边框样式：无边框、实线、虚线。
- 边框颜色。
- 边框粗细。
- 尺寸。
- 旋转角度，既支持拖拽旋转，也支持数值输入。
- 是否进入图例。
- 图例名称。

交互行为：

- 用户点击画布创建三角形。
- 创建后可以旋转。
- 创建新三角形时复制选中对象或上次使用样式。

### 2.6 共享图元：半透明标注框

用于：

- 消防转弯半径标识，例如 `R=9M`。
- 竖向标高标识。

需要控件：

- 文字内容。
- 字号。
- 标注框宽度。
- 标注框高度。
- 标注框不透明度。
- 内边距。

颜色规则：

- 标注框颜色跟随父级箭头或三角形颜色，并使用半透明背景。
- 文字颜色必须与父级箭头或三角形颜色保持一致，不再提供其他颜色规则，避免执行计划出现两可解释。

交互行为：

- 转弯半径标注框跟随转弯半径箭头。
- 标高标注框跟随标高三角形。

### 2.7 共享图元：箭头文字

用于：

- 竖向坡度箭头，例如 `0.3%`。

需要控件：

- 文字内容。
- 字号。
- 沿箭头方向的位置偏移。
- 垂直箭头方向的位置偏移。

行为规则：

- 不带半透明标注框。
- 文字颜色跟随箭头颜色。
- 文字自动旋转到与箭头方向平行。

### 2.8 配图上传

配图上传不是画布绘图能力，而是图纸类型的附加素材能力。用户需求已经明确配图最终由 agent 根据数量在 PPT 中自动排版，因此本轮不支持、也不要求用户把配图手动摆放到绘图画布上。

这是本轮除 semantic JSON 保存以外唯一需要新增后端接口的能力。实现时必须保证它不回退现有 task pack 生成能力。

推荐存储：

- 文件目录：`projects/{project}/05_output/drawings/supporting/{drawing_type}/`
- 清单文件：`projects/{project}/05_output/drawings/supporting/{drawing_type}/manifest.json`

清单字段：

- `id`
- `file`
- `original_name`
- `caption`
- `sort_order`
- `notes`

PPT agent 合约：

- 工作台只负责上传、列表、排序和可选说明。
- 后续 PPT/report agent 根据图片数量自动选择排版。
- 用户不需要在绘图画布上手动摆放这些配图。

### 2.9 图纸类型 ID 与后期改名风险控制

用户已确认：如果后期修改风险可控，图纸类型 ID 可以先进入 schema / page_index / task_pack。为降低风险，最终计划必须用集中 registry 管理这些 ID，不允许在前端、后端、文档生成和任务包逻辑里散落硬编码字符串。

本轮采用以下图纸类型 ID：

- `planting_design`：绿化设计图。
- `landscape_analysis`：景观绿地规划设计分析。
- `traffic_analysis`：交通组织。
- `fire_route`：消防流线。
- `vertical_analysis`：竖向分区图。
- `supporting_facilities`：配套分析图。
- `sponge_city`：海绵城市专篇。
- `accessibility_design`：无障碍设计专篇。
- `civil_defense`：人防设计专篇。

风险控制要求：

- 前端工作台列表、中文标题、默认工具、默认对象类型都从同一个 drawing registry 读取。
- 后端 schema、保存路径、task pack、reference page index 也应从同一组常量或等价 registry 派生。
- 如果后续必须改 ID，应该新增 alias/migration，把旧 ID 读入为新 ID，而不是直接破坏旧文件路径和旧 JSON。
- 中文显示名可以改，英文 ID 不随 UI 文案随意变动。

### 2.10 图例分组规则

最终计划必须明确图例如何从对象列表生成，不能只写“进入图例”。

推荐分组键：

- 多边形 path：`object_type + legend_label + fill_mode + fill_color + fill_opacity + hatch_angle + hatch_spacing + border_style + border_color + border_width`。
- 线段 path：`object_type + legend_label + stroke_color + stroke_width + stroke_style + start_arrow + end_arrow + arrow_size`。
- 圆形标记：`object_type + legend_label + fill_mode + fill_color + fill_opacity + border_style + border_color + border_width + double_border_gap`。
- 三角形标记：`object_type + legend_label + fill_mode + fill_color + fill_opacity + border_style + border_color + border_width`。三角形的实际旋转角度不参与图例分组。
- 转弯半径箭头、坡度箭头等带文字对象：默认不自动合并文字内容；如果 `legend_enabled=true`，按 `object_type + legend_label + stroke_color + stroke_width + stroke_style + arrow_size` 分组。

图例行为：

- `legend_enabled=false` 的对象不进入图例。
- 同一分组键下多个对象只生成一个图例条目。
- 图例名称优先使用对象的 `legend_label`；没有时使用该对象类型的默认中文名。
- 标记类对象统一使用“一个对象类型 + 用户自定义图例名/颜色”的模式，因此图例分组必须尊重逐对象样式，而不是只按对象类型合并。

## 3. 每张图纸的工作台配置

### 3.1 `planting_design` / 绿化设计图

对象类型：

对象类型：

验收标准：

## 6. 已确认决策与剩余问题

### 6.1 已确认决策

这些内容后续写 `/goal` 实施计划时不再作为开放问题处理：

1. 本轮只做语义层：`semantic JSON + task pack + 配图 manifest`。不恢复 SVG/PPT 渲染，不做自动成品图生成。
2. 图纸类型 ID 采用第 2.9 节列表。实施时用集中 registry 和 alias/migration 降低后期改名风险。
3. 线段模型统一为开放 path，支持 N 个点，每段都可为直线或弧线。两点线段只是最简单的创建方式。
4. 配图上传只做上传、列表、排序和说明，不在画布上手动摆放。
5. 景观节点、出入口等标记类对象采用单对象类型，由用户自定义颜色、尺寸、填充和图例名，不预设主/次/车库等固定标记子类型。
6. 转弯半径箭头第一版做直箭头，两个端点确定方向；不做弧形转弯箭头。
7. 标注框文字颜色必须与父级箭头或三角形颜色一致。
8. 旧功能分区语义 JSON 必须无损兼容读入，尤其是 `polygon + segments` 弧线对象。
9. 图例必须按第 2.10 节定义分组键，支持线段、圆形、三角形和多边形按样式合并。

### 6.2 仍需在实施计划中给出默认值的问题

这些不再阻塞写计划，但计划必须给出明确默认值，不能留给执行 agent 猜：

1. 斜线填充默认值：建议默认 45 度，间距使用画布归一化尺寸或像素换算后的固定视觉间距；仍提供角度、间距、线宽控件。
2. 圆形双实线边框：按“两条同心圆描边 + 可调间距”实现；计划中需要固定默认间距。
3. 标高标注框：建议第一版固定附着在三角形上方或右上方，并提供偏移输入；是否支持鼠标独立拖动由计划按复杂度决定。
4. 无障碍设计：第一版按用户需求只做圆形、多边形和配图；无障碍流线暂不启用，除非后续用户追加。
5. 底图策略：人防必须支持独立底图；建议计划直接实现每个图纸类型各自保存底图路径，避免默认共用全局底图。
