用户要求先讨论和梳理还缺哪些图纸工作台，再逐张图纸确认需要的绘图工具。不同图纸不一定使用与功能分区完全相同的工具，例如绿化设计图需要线段，景观分析不需要多边形但需要线段和景观节点图案。交通分析工作台虽然已经存在，但属于早期实现，也需要按照功能分区工作台的成熟实现重构。

用户逐项提出的完整需求如下：

1. 日照分析由专业软件完成，在这里仅需要上传图纸即可；但不需要在本轮单独做日照工作台上传图纸功能，上传图纸会在另外环节完成。

2. 绿化设计图需要线段功能。除当前多边形必须围合才能生成图形的能力外，还要支持点击两个端点生成线段。线段也要拥有多边形线段的中心点弧线功能。多边形需要增加斜线填充选项，也就是在当前半透明填充之外增加斜线填充；当前只有有填充和无填充。线段也必须作为图例的一种。绿化设计图还需要配图上传功能，用户可以上传任意张配图，最后由 agent 根据配图数量在 PPT 中自行最优排版。

3. 景观绿地规划设计分析需要相同的线段功能，并且线段粗细要能任意调节，也要支持虚线和实线。这些基础功能需要参考功能分区代码。景观分析额外需要景观节点：用户点击画布即可放置景观节点。景观节点是可自由变换大小的正圆形；它像多边形一样可以选择填充或不填充，边框可实现虚线，还要支持双实线边框。用户点击已经生成好的景观节点可以选中并修改；点击画布生成下一个景观节点时，应复制选中景观节点的样式。景观分析也需要配图上传功能，景观节点也需要生成图例。

4. 交通组织需要提供前述线段的全部功能，并且线段两端可以分别选择是否带箭头。交通组织还需要用户点击画布放置出入口；出入口是等边三角形，创建以后可以任意旋转，能力类似景观节点，但还要提供实心填充能力。当前所有填充都是半透明填充。

5. 消防流线设计图需要前述线段能力。此外需要新增转弯半径能力：用户点击两个端点生成一个箭头，并确定箭头方向。箭头颜色和大小都可以调节。箭头自带一个半透明方框，方框内是与箭头同色的转弯半径标识，例如原设计图中的 `R=9M`。方框大小和字体大小都可以调节，但颜色要与箭头保持一致。调好一个箭头样式后，后续点击画布生成的箭头都应继承之前样式。

6. 竖向分区图需要标高和坡度能力。标高是等边三角形，可以参考出入口三角形代码，但标高三角形上需要自带类似消防流线中转弯半径标识的半透明方框，方框大小和字体也可调。坡度能力类似前述箭头能力，但箭头上可以输入坡度，例如 `0.3%`；这个文字不带半透明方框，但文字必须自动平行于箭头方向，颜色和箭头保持一致。

7. 配套分析图提供与功能分区一样的多边形能力，以及与景观节点一样的圆形能力。这个圆形可以选择实心填充或半透明填充，名称为垃圾收集点。配套分析图也提供配图上传功能。

8. 海绵城市专篇分析图提供多边形能力、线段能力和配图上传功能。

9. 无障碍设计专篇提供圆形功能、多边形功能和配图上传功能。

10. 人防设计专篇提供多边形功能。

## 2. 推荐统一设计

不要为每张图纸各写一套绘图逻辑。正确做法是：一套共享图元系统，加每张图纸自己的工具配置。

### 2.1 共享图元：路径 path

路径同时覆盖闭合多边形和开放线段。

建议字段：

- `geometry.kind`: `path`
- `geometry.closed`: `true` 或 `false`
- `geometry.segments`: 由 `line` 或 `quadratic` 段组成的数组
- `geometry.coords`: 给旧逻辑或预览使用的采样坐标

行为定义：

- `closed=true` 表示多边形。
- `closed=false` 表示开放线段、折线、箭头线。
- 每一段都可以是直线或二次贝塞尔曲线。
- 当前功能分区里的“线段中心点拉弧线”能力，应该迁移成 path 的通用能力，闭合多边形和开放线段都能使用。

为什么必须这么做：

- 用户明确要求线段也支持多边形线段的中心点弧线功能。
- 当前 schema 强制 `segments` 闭合，无法表达开放线段，这是后续所有线性图纸的共同阻塞点。

### 2.2 共享图元：多边形样式

适用于 `closed=true` 的 path。

需要控件：

- 填充模式：无填充、半透明填充、实心填充、斜线填充。
- 填充颜色。
- 半透明填充的不透明度。
- 斜线填充角度。
- 斜线填充间距。
- 斜线颜色或默认跟随填充颜色。
- 边框样式：无边框、实线、虚线、双实线。
- 边框颜色。
- 边框粗细。
- 是否进入图例。
- 图例名称。

兼容现状：

- 当前功能分区的 `fill_enabled=true` 可迁移为 `fill_mode=translucent`。
- 当前功能分区的 `fill_enabled=false` 可迁移为 `fill_mode=none`。

### 2.3 共享图元：线段样式

适用于 `closed=false` 的 path。

需要控件：

- 线条颜色。
- 线宽，使用数值输入或滑块，不能只有固定三档。
- 线型：实线、虚线。
- 每段支持弧线控制点。
- 起点箭头：开/关。
- 终点箭头：开/关。
- 箭头大小。
- 是否进入图例。
- 图例名称。

### 2.4 共享图元：圆形标记

用于：

- 景观节点。
- 垃圾收集点。
- 无障碍设施点。

几何字段：

- 圆心坐标。
- 半径。

需要控件：

- 拖拽调整大小，并始终保持正圆。
- 填充模式：无填充、半透明填充、实心填充。
- 填充颜色。
- 填充不透明度。
- 边框样式：无边框、实线、虚线、双实线。
- 边框颜色。
- 边框粗细。
- 双实线间距。
- 是否进入图例。
- 图例名称。

交互行为：

- 用户点击画布创建圆形节点。
- 用户点击已生成节点可以选中并修改。
- 如果已有选中节点，再创建下一个同类节点时，新节点复制选中节点样式。
- 如果没有选中节点，则复制该对象类型的上一次使用样式。

### 2.5 共享图元：三角形标记

用于：

- 交通出入口。
- 竖向标高点。

几何字段：

- 中心点坐标。
- 尺寸。
- 旋转角度。

需要控件：

- 填充模式：无填充、半透明填充、实心填充。
- 填充颜色。
- 填充不透明度。
- 边框样式：无边框、实线、虚线。
- 边框颜色。
- 边框粗细。
- 尺寸。
- 旋转角度，既支持拖拽旋转，也支持数值输入。
- 是否进入图例。
- 图例名称。

交互行为：

- 用户点击画布创建三角形。
- 创建后可以旋转。
- 创建新三角形时复制选中对象或上次使用样式。

### 2.6 共享图元：半透明标注框

用于：

- 消防转弯半径标识，例如 `R=9M`。
- 竖向标高标识。

需要控件：

- 文字内容。
- 字号。
- 标注框宽度。
- 标注框高度。
- 标注框不透明度。
- 内边距。

颜色规则：

- 标注框颜色跟随父级箭头或三角形颜色。
- 文字颜色也跟随父级颜色，或者使用同色加深版本；最终执行计划需要固定一种规则。

交互行为：

- 转弯半径标注框跟随转弯半径箭头。
- 标高标注框跟随标高三角形。

### 2.7 共享图元：箭头文字

用于：

- 竖向坡度箭头，例如 `0.3%`。

需要控件：

- 文字内容。
- 字号。
- 沿箭头方向的位置偏移。
- 垂直箭头方向的位置偏移。

行为规则：

- 不带半透明标注框。
- 文字颜色跟随箭头颜色。
- 文字自动旋转到与箭头方向平行。

### 2.8 配图上传

配图上传不是画布绘图能力，而是图纸类型的附加素材能力。

推荐存储：

- 文件目录：`projects/{project}/05_output/drawings/supporting/{drawing_type}/`
- 清单文件：`projects/{project}/05_output/drawings/supporting/{drawing_type}/manifest.json`

清单字段：

- `id`
- `file`
- `original_name`
- `caption`
- `sort_order`
- `notes`

PPT agent 合约：

- 工作台只负责上传、列表、排序和可选说明。
- 后续 PPT/report agent 根据图片数量自动选择排版。
- 用户不需要在绘图画布上手动摆放这些配图。

## 3. 每张图纸的工作台配置

### 3.1 `planting_design` / 绿化设计图

启用工具：

- 多边形路径。
- 开放线段路径。
- 配图上传。

对象类型：

- `planting_zone`：普通绿化区域，多边形。
- `key_planting_zone`：重点绿化区域，多边形。

## 6. 实施前需要讨论的问题

1. 配图上传：工作台是否只负责上传、列表、排序和说明，还是用户也需要把配图手动摆放到绘图画布上？当前建议是不手动摆放，由 PPT agent 后续自动排版。

2. 线段绘制：用户说“点击两个端点”。第一版是否严格限制为两点线段，还是允许继续添加点形成多段折线？当前建议是先支持两点线段，同时在不增加复杂度的前提下支持继续添加点。

3. 斜线填充：是否一个默认 45 度斜线足够，还是需要角度、间距、线宽都可调？

4. 圆形双实线边框：是否按“两条同心圆描边 + 可调间距”实现？默认间距建议多少？

5. 景观节点：是否区分“主要景观节点”和“次要景观节点”的默认样式，还是只保留一个节点类型，让用户自行改图例名和颜色？

6. 出入口三角形：是否需要主入口、次入口、车库入口三个预设，还是一个三角形标记加用户自定义图例名和颜色即可？

7. 转弯半径箭头：用户描述是“点击两个端点确定箭头方向”。第一版是否做直箭头即可，还是必须做成弧形转弯箭头？

8. 标高标注框：标注框默认固定在三角形上方/右侧即可，还是需要允许独立拖动位置？

9. 无障碍设计：是否要在第一版加入无障碍流线工具？当前用户要求只有圆形、多边形和配图。

10. 底图策略：人防明显需要独立底图。是否每个图纸类型都默认保存自己的底图路径，而不是共用一个全局底图？

11. 图纸类型英文 ID 是否确认使用以下命名：
    - `planting_design`
    - `landscape_analysis`
    - `traffic_analysis`
    - `fire_route`
    - `vertical_analysis`
    - `supporting_facilities`
    - `sponge_city`
    - `accessibility_design`
    - `civil_defense`

12. 范围边界：本轮是否只做到 semantic JSON、task pack 和配图 manifest，不恢复最终 SVG/PPT 渲染？这与历史 roadmap 中“暂停 deterministic render / final output”的说明一致。
